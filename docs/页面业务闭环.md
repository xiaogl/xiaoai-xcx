# 小程序页面业务闭环审计

审计对象为 index.html 加载的用户端脚本。下表按 XA.page 注册名索引，可搜索路由或动作名。后台列描述本页实际消费的运营数据或交易接口；仅有后台演示视图不能证明用户操作已同步。门店列中的「—」表示本页没有独立门店操作。逐页结论基于代码走读。文末单列主任务提供的线上实测与本地验证范围；真实资金、微信推送和跨账号权限尚未验证。

## 持久化边界

- **共享**：operations 客户端按 demo 空间访问 /api/operations；处理器读写私有 Blob 的 demo/v2/<空间>.json，条件写入失败返回冲突。相同空间内可重新读取。空间标识用于演示隔离，不能证明真实顾客或员工身份。
- **目录**：启动与页面重新可见时 loadCatalog 读取已发布资料，覆盖 XA.data 的对应字段。未配置的资料可能来自 data.js 自带种子。目录可维护与用户行为可回写是两件独立的事。
- **本机**：XA.save 将 XA.state 序列化到 localStorage 的 xa_proto_v17。清除站点数据会丢失个人记录；切换演示登录状态不构成账号隔离。临时表单、筛选或弹层常在 XA.tmp、模块变量或 DOM 中。
- **支付与履约**：订单或预约状态写入共享存储，只证明业务记录已提交。模拟收款、退款文案、二维码图案、订阅弹窗及奖励积分分别核对，不能视为渠道回执。

## 到店链路复核要点

1. 门店目录中 store.staff 为技师 ID 集合。新增预约仅展示已关联且 enabled 不为 false 的人员；历史单读取保存的 staffName。any 是分配意向，成功后以服务端实际分配为准。
2. shifts 以星期日 0 至星期六 6 索引。未设置当天时段表示使用全部基础时段，空数组表示当天休息。slotOverrides 的 full 关闭门店时段；忙闲还受同一技师跨店预约时长影响。改期计算剔除原单。
3. 核销、取消和改期均等同步接口确认后刷新。后端冲突或排班变更会提示并重新读目录。核销后 doneAt 是持久记录，客户端演示的积分、订阅消息与真实支付渠道仍需独立履约链路。
4. 验收共享时使用同一个 demo 参数，在另一窗口重读目录，对照预约 ID、技师 ID、状态和活动剩余席位。两个不同空间的数据不能作为同步对照；同一浏览器内立即出现的成功提示也不能证明跨端持久化。

## 验证记录与后续开发缺口

- **线上实测（主任务提供，三个独立浏览器）**：运营后台新建技师 → 门店端修改职称 → 用户端指定该技师预约 → 门店端核销 → 两端刷新均显示已完成，用户端增加 50 积分。此证据覆盖同一演示空间内的预约与核销链路。
- **本地验证**：在内存中直接调用 storeOperation 并使用前端时段计算，检查停用、空排班、any 分配、占用、改期释放、取消与核销；活动与候补使用用户端动作函数连接同一业务处理器，检查报名后席位减一、取消后恢复，以及候补登记、释放与取消。上述检查不经过网络存储。其余逐页结论来自静态审计。
