# 晓艾门店经营系统

## 本地运行

在 xcx 目录使用 Node.js 24 运行 `node scripts/local-preview.mjs`，打开 http://127.0.0.1:4174/merchant/ 。本地 API 使用和项目相同的门店业务逻辑，演示数据按空间写入用户目录下的 .xiaoai-local-preview。可以通过 XIAOAI_PREVIEW_DATA 指定其他数据目录。仅监听本机。

首次进入某个演示空间的门店时，浏览器建立老板凭证。老板在「角色与终端」签发前台、老板或指定技师的入口。授权入口可以撤销。首次开通、历史顾客端和平台运营端沿用演示空间机制，正式客户资料不应录入演示环境。

## 日常工作

- 前台在客户档案登记服务偏好和下次回访日期。在「预约核销」代客预约，或为散客直接开单。预约接待时选择客户并核对技师与项目。
- 服务单占用一位技师和一间房或一个床位。服务结束后释放资源。技师可在手机上完成本人服务并留给前台结算。
- 前台可按现金、微信或支付宝登记收款，也可扣减疗程卡或使用已发给客户的优惠券。预约开单会抵扣预约上记录的定金。
- 老板登记支出、办理退款、查看提成并导出流水。次卡退款操作指单次服务撤销扣次，退回对应次数。交班按上次交班之后的流水计算现金净额，记录盘点差异。
- 新服务单按开单时的提成比例计算。次卡服务按项目价格计提。财务模块反映门店收支登记，真实支付与银行清算另行对接。
- 「员工与提成」可进入员工档案与周排班。原门店预约、候补和活动名额页面保留在 scheduling.html。

## 微信小程序开发预览

用微信开发者工具导入 merchant-mini 目录，使用测试号或自己的 AppID。在电脑老板端签发老板或指定技师入口，复制界面显示的启动参数，为 pages/work/index 建立自定义编译模式。本机 API 地址在 merchant-mini/app.js。开发者工具模拟器使用本地 HTTP，真机联调需要可访问的服务地址。

老板端展示服务、预约、排班及经营汇总。员工端仅返回该技师的预约、服务单、相关客户姓名与服务偏好、排班和提成。下拉刷新读取同一门店的服务数据。

## 商用前待交付需求

| 工作项 | 验收条件 |
| --- | --- |
| 租户与组织 | 手机号或微信身份完成登录，企业管理员邀请员工；所有历史 API 和新工作台统一检查组织、门店和字段权限；离职后全端失效。 |
| 微信真机交付 | 配置企业 AppID、业务域名及隐私授权，老板和技师分别在 iOS 与 Android 验收，测试预约订阅通知。 |
| 支付与对账 | 支付回调、退款回调及每日渠道账单可重复处理，实收、定金、储值负债、退卡及差异可追溯。 |
| 人员薪资 | 支持底薪、轮牌、点钟、跨店支援和多技师分成；锁定月度工资单后，冲正保留双向流水。 |
| CRM 与营销 | 客户授权及撤回、客户合并、跨店权益、卡有效期和退转卡、生日活动与触达结果可追溯。 |
| 行业服务 | 房间与多床位层级、清洁与通风间隔、服务记录模板、耗材批次及耗用成本与工单关联。 |
| 连锁及可靠性 | 总部按店对比，数据库迁移、备份恢复、并发压测、审计导出和异常告警通过验收。 |

## 本地扫码收银与晓艾顾客端

顾客登录晓艾后可直接从「我的 → 到店账单与余额」查看本人各门店记录。门店 CRM 与顾客预约共用会员 ID，已有档案按登录手机号自动识别，原账单和余额保留。演示登录使用固定测试手机号 13800006608。

单次服务结束后可结账。前台在「前台接待 → 会员充值」为客户建立充值单，或由客户在晓艾中自助演示充值。顾客可以直接支付，也可以为待付账单出示付款码。前台在同一账单选择「扫码收款」。设备采用 USB 或蓝牙键盘模式，启用交叉二五码（ITF）并以回车结束输入；本地测试也可键入条码数字再按回车。付款码绑定门店、客户、账单和金额，90 秒有效，仅能成功使用一次。

余额支付扣减储值，不增加现金实收。充值到账、账单结算及财务流水在同一次状态更新中提交；余额支付的服务退款退回原门店余额。演示渠道与微信、支付宝商户账户相互独立。
